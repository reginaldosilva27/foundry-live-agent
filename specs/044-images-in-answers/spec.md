# Spec: Images in an answer

|---|---|
| **ID** | 044-images-in-answers |
| **Status** | draft |
| **Author** | Reginaldo Silva |

## Problem / motivation

The app has no images in it and the agent has no way to produce one. The request that prompted this
spec was "gerar imagens", and it is worth separating the three things that phrase can mean, because
only one of them is UI work:

1. **The agent produces an image** — a tool, a model deployment, a definition change. Most of the
   work, and none of it in the frontend.
2. **The image reaches the browser** — a URL in the answer, or bytes somewhere. A contract question,
   and the place where the tempting wrong answer lives.
3. **The browser shows it well** — sizing, alt text, saving, theme. A small amount of frontend work.

The tempting wrong answer is a tenth `AgentEvent`. It is wrong twice: a change to the event set needs
a spec and moves every consumer and fixture with it (§9), and it would be spent transporting a URL,
which `text_delta` already transports. An image that arrives as Markdown needs no contract change at
all.

The honest position is that this spec is mostly not about the UI, and it is deferred behind the rest
of the map for that reason.

## Goals

- **The agent can produce an image**, through a tool, executed by whichever side the harness makes
  responsible.
- **The image renders in the answer**, sized, labelled and saveable.
- **No new event type**, and no change to the contract.

## Non-goals

- **No `image` event.** The contract stays nine types (§9). If the clarify step concludes an image
  genuinely cannot travel as text, that is a contract change and this spec must be rewritten as one
  before any code is written — not amended during implementation.
- **No image input** — sending an image *to* the agent is spec 045's territory.
- **No editing, cropping or annotation.**
- **No image generated by the app.** The app does not call an image model; it renders what the agent
  produced (§8).
- **No guessing what an image is.** An image with no description from the tool gets no invented alt
  text (§5).

## User-facing behavior

All new prose ships `{ en, pt }` (§7).

**An image in an answer** renders inline at a size that fits the conversation column, never
overflowing it, with the aspect ratio preserved and a placeholder holding its space while it loads so
the answer does not jump.

**It carries a description** — the alt text — taken from what the tool returned. When the tool
returned none, the image is presented as an image with no description available, which is a true
statement and useful to a screen-reader user in a way that a generated guess is not.

**Selecting it** opens it larger, in an overlay with the app's existing focus behaviour.

**Saving it** is offered, and the turn's Markdown export carries its URL (`exportTurn.ts`).

**An image that fails to load** renders as a failure with its URL visible and copyable — usually an
expired link, which is worth being able to see.

**A generation that failed** is a `tool_result` with an error, and renders as a failed tool exactly
like any other (spec 009). Nothing special happens because it was an image.

## Acceptance criteria

1. **AC1** — An image URL in an answer renders inline, fitted to the column, with its aspect ratio
   preserved, and never causes horizontal scrolling.
2. **AC2** — Space is reserved while it loads; the answer does not shift when it arrives.
3. **AC3** — The description comes from the tool's output; with none, the image renders as having no
   description available — never a generated one (§5).
4. **AC4** — Selecting an image opens an overlay that traps focus and returns it on close.
5. **AC5** — An image can be saved, and the Markdown export carries its URL.
6. **AC6** — An image that fails to load renders a failure with its URL visible and copyable.
7. **AC7** — A failed generation renders as a failed tool call, with no image-specific handling.
8. **AC8** — No new event type is introduced; the contract remains the nine types (asserted by the
   existing contract tests, unchanged).
9. **AC9** — The frontend issues no request to produce an image (asserted — the §8 guard).
10. **AC10** — Every new string ships `en` + `pt`.

## Contract / data impact

| | |
|---|---|
| **BFF / `AgentEvent`** | **Unchanged, and that is a requirement of this spec** (§9). The image travels as a URL in `text_delta`, or as a URL in a `tool_result` the answer then references. |
| **Agent definition** | A new tool in `agent_core.yaml`, shared by both harnesses (§4), implemented once in `ai/harness/_shared/tools/` like the other three. A new agent version applied for both. |
| **§10** | Which image model Foundry serves, under which SDK call and `api-version`, and what its output looks like — a URL with a lifetime? base64? — comes from a doc read at the time of writing and recorded in `docs/REFERENCES.md`. Nothing about this is guessed. |
| **Secrets** | If the image service is an Azure one, `DefaultAzureCredential` as everywhere. If it is not, that is a **third** third-party key after Tavily, and the constitution requires saying why and where the reader hits it — which is a reason to prefer an Azure path. |
| **Content Security Policy / origins** | The browser would load an image from an origin that is not the BFF — the first time it talks to anything else. That deserves a sentence in the plan, and possibly a proxy through the BFF instead. |
| **Docs** | `docs/architecture.md`, `docs/REFERENCES.md`. |

## Open questions (clarify before planning)

- [ ] Does the image URL have a lifetime? An answer stored in this browser's history (021) whose
      image expires in an hour renders a broken image forever after. Does the app say so?
- [ ] Does the browser load the image directly, or does the BFF proxy it — which keeps "the browser
      talks to the BFF and nothing else" true?
- [ ] Base64 in a tool output would blow up the SSE stream and this browser's storage. Is it ruled
      out explicitly?
- [ ] Is there a use for this in the project's actual subject matter, or is it a capability demo? The
      answer decides whether it ships at all.

## Out of scope / deferred

- Images as input (spec 045).
- Editing or annotating images.
- Any image the app itself generates.
