# Spec: The agent speaks while it works — and sounds better doing it

| | |
|---|---|
| **ID** | 016-speaks-while-it-works |
| **Status** | done |
| **Author** | Reginaldo Silva |
| **Date** | 2026-09-16 |

## Problem / motivation

Voice mode goes silent exactly when it should be most convincing.

Observed 2026-09-16, asking *"can you check on internet what is the last game of Corinthians?"*:
the overlay filled with four tool rows — `search_web` 2.0 s, `search_web` 3.2 s, `search_web` 1.6 s,
`get_current_datetime` 4 ms — and the agent said **nothing at all** for the whole round trip. The
first sound the user hears is the finished answer, seven seconds later. On screen the app is
visibly working; in the ear it is indistinguishable from a broken session.

This is the failure spec 006 and spec 012 were written to avoid, arriving through a different door.
Spec 006 made sure an unanswered function call can never leave the agent mute mid-turn; spec 012
made sure the session negotiates audio rather than text. Both hold. What neither addresses is that
a *correctly working* tool round trip is silent by construction: the model emits a function call
instead of speech, and speech resumes only after the output comes back. In a text chat that gap is
a spinner. In a spoken conversation it is a person who stopped talking to you.

The second complaint landed in the same session: **the Portuguese does not sound good.** The current
default, `pt-BR-Luana:MAI-Voice-2-Flash`, was chosen in spec 012 from documentation — "optimized for
real-time responsiveness" — and that spec recorded, honestly, that *accepted is not the same as
good* and that no listening test had been run. One has now been run, by the person this project is
built for, and the verdict is that the HD tier is worth the latency.

## Goals

- A tool round trip in voice mode is **audibly** explained: before the agent goes quiet to call a
  tool, it says one short sentence about what it is about to look up.
- That sentence is in the language the user is speaking, like every other answer.
- The same behavior in the text chat is welcome, not merely tolerated: a line of intent above the
  tool rows is what the activity panel already shows visually.
- The default Portuguese voice becomes the HD tier, and the trade it makes is written down where
  the next reader will hit it.

## Non-goals

- **No filler audio generated by this app.** The BFF does not synthesize "one moment" over the
  gap, and does not inject text for the agent to speak. What the agent says is the agent's, or the
  demo stops being a demo of Foundry (§8).
- **No per-session `instructions`.** The Voice Live documentation is explicit that `instructions`
  is not supported with a custom agent, so there is no voice-only lever to pull; spec 012 already
  decided this and it stands.
- No change to the `AgentEvent` set (§9). Nothing new needs to cross the contract — a preamble is
  ordinary agent speech, and in voice it never reaches the BFF at all.
- No UI change. The overlay already lists the calls; this spec is about the audio.
- No per-session voice picker in the UI — still one configured voice per deployment (spec 012).
- No promise that the model narrates *every* time. Instructions bias a model; they do not compel it.

## User-facing behavior

**In voice mode.** The user asks something that needs a tool. Within a beat the agent says a short
sentence — *"Deixa eu procurar isso na web."* / *"Let me look that up."* — names what it is going
after, then goes quiet while the tool runs, then answers. The silence that remains is bounded by
the tool, and it is now explained.

**In the text chat.** The same sentence arrives as a short line of streamed text immediately above
the tool rows it explains.

**i18n (§7).** No new strings ship in `strings.ts`: the sentence is produced by the model in the
user's language, under an instruction that says so. The bilingual obligation here falls on the
documentation, not on the UI.

**The voice.** Portuguese is read by `pt-BR-Thalita:DragonHDLatestNeural`. Anyone preferring the
low-latency tier sets `VOICELIVE_VOICE` back to `pt-BR-Luana:MAI-Voice-2-Flash`; both are listed,
with the trade, in `.env.example`.

## Acceptance criteria

1. **AC1** — Given the shipped agent definition, when it is loaded, then its instructions require
   one short sentence, in the user's language, stating what is about to be looked up, sent
   **before** calling a tool that takes a moment.
2. **AC2** — Given the same instructions, then they do **not** ask the agent to name the tool's
   identifier or otherwise speak in jargon, and they do not turn the preamble into a running
   commentary on every call in a multi-call turn.
3. **AC3** — Given a **live** text turn that calls at least one tool, when it is recorded, then the
   recording shows `text_delta` for the preamble arriving before that turn's first `tool_call`
   event, and the recording is committed as a fixture dated the day it was taken (§5, §10).
4. **AC4** — Given a **live** voice turn that calls at least one tool, when it is recorded, then
   the control-channel recording shows the agent's audio transcript for the preamble arriving
   before `response.function_call_arguments.done`, committed the same way.
5. **AC5** — Given no `VOICELIVE_VOICE` in the environment, when settings load, then the configured
   voice is `pt-BR-Thalita:DragonHDLatestNeural`, sent as type `azure-standard`.
6. **AC6** — Given the default voice, then every place that states it agrees: the settings default,
   the environment default, `.env.example`, and the documented session frame. A drift between the
   code default and `.env.example` fails a test, not a review (§4).
7. **AC7** — Given a **live** voice session started with the new default, when `session.created` /
   `session.updated` arrives, then the negotiated voice echoes `pt-BR-Thalita:DragonHDLatestNeural`
   — i.e. the HD tier is served to this project's own resource, in its own region — and the
   observation is recorded in `docs/REFERENCES.md` with its date.
8. **AC8** — Given the existing voice and chat suites, then they still pass unchanged: no behavior
   outside the agent definition and one configuration default moves.

## Contract / data impact

- **`AgentEvent` (§9): unchanged.** A preamble is `text_delta` in chat, and in voice it is audio
  the browser already plays. This spec adds nothing to the contract and removes nothing.
- **The agent definition** `ai/harness/prompt_agent/agent.yaml` is the single source of truth for
  instructions. Changing it requires re-applying the agent (a new immutable version) for the
  behavior to exist in Foundry — the change is not live until then, and the spec is not done until
  it is.
- **The default voice** has one source of truth in the backend settings; `.env.example` and the
  Voice Live lifecycle doc mirror it and must move in the same commit (§4). Spec 012's "Clarified
  decisions" recorded the old default and is amended, not rewritten — the reasoning stays visible.

## Open questions (clarify before planning)

Every question that needed a person is answered. The last one needs the **live service**, and is
answered by AC3/AC4 rather than by a conversation.

- [x] What should the preamble say? → **A short sentence naming what it is about to look up**, in
      the user's language; no tool identifiers. (User, 2026-09-16.)
- [x] Voice-only or both modalities? → **Both.** There is no voice-only lever (`instructions` is
      unsupported with a custom agent), and the line is wanted in chat too. (User, 2026-09-16.)
- [x] Which Portuguese voice? → **`pt-BR-Thalita:DragonHDLatestNeural`**, chosen by listening,
      accepting the HD latency trade. (User, 2026-09-16.)
- [x] Does `gpt-5.5` actually emit speech before a function call under this instruction, on both
      the Responses API and Voice Live? → **Yes, in both**, recorded 2026-09-16 against agent
      version 6 and committed as `prompt-agent-preamble-20260916.jsonl` and
      `voice-live-preamble-20260916.jsonl`. Text: *"Vou verificar na web e confirmar a data atual
      para identificar o jogo mais recente."* Voice: *"Vou verificar isso na internet agora."*
      Unasked-for finding: it narrates **once per leg**, not once per turn — better than the rule,
      because each leg is its own silence.

## Out of scope / deferred

- A `response.create` carrying a filler instruction while the tool runs — closer to the app
  speaking for the agent than this project should go.
- A UI affordance for "the agent is working" inside the voice overlay beyond the existing rows.
- Making the preamble configurable per deployment. One agent definition, one behavior.
